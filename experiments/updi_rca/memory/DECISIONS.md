No flash, fuse, USERROW, EEPROM, BOD, reset, or target data-memory write was performed in the current session. The six observed `STCS` setup transactions in the legacy probes changed UPDI control configuration only; the strict baseline path does not emit them.

## FLAG_RX follow-up decision

The read-only GPR2 campaign is now the controlling evidence for the “RX always active” report: `LDS 0x001e` returned `0x03` in 100/100 sequential Lane A reads, with `FLAG_RX` and `FLAG_ENABLE` set throughout and median/p95 latency 147.597/150.083 ms. Treat this as persistent observed register state, not 100 fresh receive events; do not infer message source or reset cause from it. No virtual-UART payload writes were issued.

The inspected upstream helper labels `FLAG_RX` as “RX buffer full” and clears it only when `updi_uart_rx()` reads GPIOR3. The direct LDS probe does not clear the bit. Since current firmware identity is unknown, apply this only as a protocol interpretation; keep the host-to-target virtual-UART flag separate from target-to-host OCD bytes.
